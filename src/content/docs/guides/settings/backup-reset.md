## 大改设置或换机前，先做备份

**入口：元书首页 →「备份与恢复」。**

1. 先阅读下方备份范围限制，确认需要保留的键盘侧最新用户词已妥善回收，重要剪贴板图片已另存。
2. 确认备份保存位置：本机，或开启「使用 iCloud 存储备份文件」并确认 iCloud 可用。
3. 点击「备份」旁的「运行」。
4. 等待完成，检查下方备份列表是否出现新文件。
5. 将重要备份另存到可独立找回的位置；使用 iCloud 时，确认文件实际位于云盘并等待上传完成，不要只凭开关判断已有云端副本。

备份包含应用配置、方案、字体、皮肤、工具栏、键盘菜单、符号栏、命令动作及应用数据库等内容。它比仅导出一份应用设置文件范围更广；但不要假定它能代替所有外部文件、系统授权或服务商账号的重新配置。

:::caution[备份不等于所有数据的完整快照]
- **键盘侧最新用户词不一定已包含。** 备份读取应用侧 RIME 目录，不会先自动回收键盘侧数据。部署或同步前的回收受「禁止复制键盘文件」及文件筛选规则影响；回收前先核对当前方案目录和「自动从 iCloud 复制文件」，避免云端旧文件覆盖本地修改。保留好现有应用文件，再按[键盘文件回收说明](/apps/hamster/v3/docs/guides/faqs/how-to-copy-keyboard-files/)处理，完成后重新备份。
- **剪贴板图片原图与缩略图不包含在当前备份中。** 数据库只记录它们的文件位置，独立的 `CoreData/images` 目录不随备份保存。换机或原图片文件丢失后，仅恢复数据库不能找回图片，重要图片请另存。
:::

备份可能包含私人常用语、剪贴板文字和配置，请不要将整个备份发到公开群中。卸载前不要仅保留一份仍在本机应用目录里的备份。

## 开关 iCloud 备份后，为什么原来的备份不见了

「使用 iCloud 存储备份文件」决定优先使用的备份位置；iCloud 目录可用时，切换开关会改变**当前查看和保存备份的路径**。

- 原路径下的文件仍保留。
- 不会自动把原有备份迁移到新路径。
- 切换后列表为空，不等于之前的文件已被删除；可以切回原位置检查。

**开启开关但无法取得 iCloud 备份目录时，应用会回退到本机目录。** 因此不能仅凭开关开启就认为备份已存入云端；卸载或换机前，务必检查文件的实际位置与上传状态。

这项设置不等于开启了方案同步、皮肤同步或自动上传全部文件。

## 怎么恢复备份

1. 先备份当前数据，避免误选旧备份后无法回退。
2. 在「备份与恢复」的列表中选择目标备份。
3. 核对文件名称和时间，再确认「恢复」。
4. 云端备份需要先完成下载；等待恢复结束，不要中途退出。
5. 检查方案目录与选中方案，按需执行 RIME 部署，再回到键盘测试。

:::danger[恢复不是追加导入]
恢复会用备份中存在的内容替换当前对应的配置、目录或数据库。恢复前新增的常用语、剪贴板、方案修改等可能被替换。不要为了“试一试”直接恢复一个来源不明的备份。
:::

## 仓输入法的旧备份能直接搬过来吗

「备份与恢复」右上角提供导入仓输入法备份的入口。当前确认提示说明：**仅支持方案、字体、剪贴板、脚本内容；不支持旧版皮肤与应用设置直接导入。**

导入旧备份不等于恢复一份完整元书备份。迁移后需重新检查皮肤和界面设置，详见[如何将仓迁移到元书](/apps/hamster/v3/docs/guides/faqs/how-to-migrate-from-hamster/)。

## 只想保存界面设置，怎么导出

**入口：元书首页 →「关于」→ 右上角「⋯」→「导出应用设置」。**

导出得到 `hamster.yaml`，用于保存或迁移应用配置。它不是包含全部方案、字体、皮肤和数据库的完整备份。

导入时在同一菜单选择「导入应用设置」。导入配置会与当前配置合并，其中的同名设置可能被改写。建议先导出当前版本；导入别人提供的配置后，也要核对方案路径等设备相关设置。

工具栏、菜单、符号栏等另有各自的导入导出入口，需要一并保留时优先使用「备份与恢复」，并注意上文的用户词和图片限制，不要只保存 `hamster.yaml`。

## 几个「重置」分别影响什么

| 操作 | 入口 | 主要作用 |
| --- | --- | --- |
| 候选文字卡片中的重置 | 键盘设置 → 候选文字 | 重置该区域相关候选显示设置 |
| 键盘高度页的重置 | 键盘设置 → 键盘高度设置 | 清除自定义高度，回到皮肤高度 |
| 滑动参数页的重置 | 键盘设置 → 滑动参数设置 | 恢复滑动识别参数 |
| 重置内置键盘 | 键盘皮肤 → ⋯ | 还原内置皮肤文件 |
| 方案重置 | RIME → 方案重置 → 运行 | 切回默认 `rime-ice`，重建应用侧共享目录和默认方案目录，并替换键盘侧对应目录 |
| 重置菜单设置 | 键盘菜单设置 → ⋯ | 还原菜单设置，可能丢失自定义菜单 |
| 重置符号栏配置 | 符号栏设置 → ⋯ | 还原符号栏配置，先导出自己的版本 |
| 重置应用设置 | 关于 → 重置应用设置 | 恢复应用界面配置，并重新还原内置皮肤 |

**「方案重置」会删除并重建应用侧 `RimeSharedSupport` 和 `RimeUserData/rime-ice`，随后替换键盘侧对应的 RIME 目录。** 默认方案目录中的个人补丁、词库修改，以及尚未回收的键盘侧数据可能丢失；其他应用侧方案子目录不会因此被整体删除，但当前方案路径会切回 `rime-ice`。执行前先妥善回收用户词、另存个人修改并备份。

**「重置应用设置」不是重装应用，也不是完整备份恢复。** 它并非所有数据的一键安全回退；如果自己改过内置皮肤，尤其要先保存副本。不要把它当作普通刷新操作。

## 怎么释放应用占用的空间

**入口：元书首页 →「关于」→「文件清理」。**

1. 等待扫描完成，查看列表中的文件或目录及大小。
2. 只勾选确定不再需要的项目，注意一级目录与子项目的关系。
3. 核对底部“已选数量、预计释放空间”。
4. 点击删除并阅读不可恢复提示，确认无误后执行。

文件清理是删除实际文件，不等于清空一份可随时重建的临时显示列表。不认识的方案、数据库、备份或资源目录先不要删；需要保留的内容先导出到其他位置。
