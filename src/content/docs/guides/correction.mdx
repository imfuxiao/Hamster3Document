元书结合键盘触摸坐标与 RIME 引擎插件（`librime-correction`），提供**「动态按键区」**与**「邻键纠错」**两项防误触能力，可以根据自己的需求分别开启这两项功能。

<Aside type="note" title="不会生效的场景">
中文九键（T9）、数字键盘、符号／表情面板以及开启「精准点按」模式时，会自动跳过动态按键区与邻键纠错，不干扰正常点击。
</Aside>

## 设置入口

打开元书应用，依次进入：**输入行为 → 纠错**。

页面分为两个独立卡片：**动态按键区** 与 **邻键纠错**，可以按需单独开启或组合使用。

---

## 一、动态按键区（事前防误触）

**默认开启。**

在按下按键的瞬间，根据当前已输入的编码和方案词频／音节转移概率，在后台动态扩大高概率下一键的**隐形触控感应区**（键盘键帽外观不变）：

- **边缘吸附**：手指落在两个相邻按键的交界处时，优先吸附到更可能输入的合法字符（例如全拼输入 `nih` 后，手指落在 `a` 与 `s` 交界偏 `s` 一侧时，自动判定为高概率的 `a`）。
- **中心安全核保护**：落点位于按键键帽中心区域时，绝不会被邻键吸走，保证刻意点击、长按与划动准确可控。
- **所见即所得**：按下高亮、气泡预览、长按符号和划动动作，均与动态判定后的按键保持一致。
- **纯 Lua 方案兜底**：对于无 RIME 词典的纯 Lua 方案，会自动通过前端轻量在线学习（按历史输入习惯）提供下一键热区预测。

### 展开设置项

开启「动态按键区」后，卡片内会展开以下两项：

| 设置项 | 默认值 | 说明 |
| --- | --- | --- |
| 强度 | `标准` | 提供 **轻柔 / 标准 / 强** 三档，控制高概率按键向相邻键边缘扩展的积极程度。 |
| 调试模式 | `关闭` | 在键盘上叠加可视化热区测试图层，用于直观观察热区变化与触控判定；关闭时彻底移除视图，无常驻开销。 |

#### 调试模式图例说明

开启「调试模式」后，键盘上会显示半透明热区框与触控摘要：

- **橙色框**：高概率预测键（扩大隐形感应区）
- **绿色框**：中低概率候选键
- **灰色框**：低概率或非合法后继键
- **红点**：最近一次触摸落点
- **左上角状态条**：`hit` 为最终判定键，`phys` 为物理最近键，`alts` 为记录的物理相邻键及距离代价

<Aside type="tip" title="建议部署一次以获得最佳热区效果">
不重新部署时，「动态按键区」也能基于方案现有的 `Prism` 索引提供基础合法后继判断；但**在「RIME → 部署」中运行一次部署**后，插件会自动为方案生成轻量的 `.touch-model.bin` 词频与音节转移模型（只读 `mmap` 加载，几乎不占内存），高概率按键的权重区分会明显更精准。
</Aside>

## 二、邻键纠错（事后候选兜底）

**默认关闭。**

当按键已经误触到旁边的相邻键时，后端不会直接改写已输入的字母，而是结合这次按键时记录的**当前皮肤真实物理相邻键坐标**，在 RIME 原生词典索引（`Prism`）中尝试检索邻键纠错词条并补充到候选栏；最终上屏仍由选词或原方案的自动上屏逻辑决定。

- **跟随皮肤真实布局**：相邻键关系按当前皮肤实际按键坐标实时计算，不写死固定桌面 QWERTY 键位表。
- **无需重新部署即刻生效**：直接复用 RIME 已加载的只读 `Prism` 索引，支持完整词库检索，无大码表剪枝丢词问题。
- **只做邻键替换**：目前仅纠正物理相邻键误按，不做漏键、多键或相邻换位。

### 展开设置项

开启「邻键纠错」后，卡片内会展开：

| 设置项 | 默认值 | 说明 |
| --- | --- | --- |
| 首键不参与纠错 | `开启` | 开启时默认当前待转换输入的第 1 码永远正确、不参与邻键替换，可避免无词频码表／音形方案因首键微偏导致首位候选跳变。关闭后允许纠正首键误触（例如全拼将 `bihao` 纠回「你好」）。 |

### 正常输入与定长码表保护

- **原生完整词优先**：当原始输入本身已经命中完整的原生正常词条（例如全拼 `nihao`、小鹤音形 `ceui` 或 `cw`「错误」）时，直接保留原生候选流，不追加纠错、不破坏唯一上屏。
- **纯码表整码约束**：对于关闭造句的定长／纯码表方案（如小鹤音形、五笔等 `enable_sentence: false` 的方案），邻键纠错要求候选完整覆盖当前输入码长，不会在输入 4 码错码时退化吐出 2 码前缀词。

## 如何验证是否生效

1. 在元书应用进入 **输入行为 → 纠错**，确认所需开关状态。
2. 首次使用或切换／更新方案后，建议在 **RIME → 部署** 运行一次部署（生成 `.touch-model.bin`）。
3. 回到输入框重新唤起键盘测试：

| 场景 | 测试方式 | 预期表现 |
| --- | --- | --- |
| 动态按键区 | 全拼输入 `nih` 后，点在 `a` 与 `s` 交界偏 `s` 一侧 | 自动吸附为 `a`，直接输入 `niha`；开启调试模式可看到 `hit:a phys:s` |
| 正常输入保护 | 全拼输入 `nihao` 或小鹤音形输入 `ceui` | 原生候选不受干扰，正常首选上屏 |
| 邻键纠错（全拼） | 开启「邻键纠错」，输入 `nihso` | 候选中尝试给出「你好」 |
| 邻键纠错（码表） | 开启「邻键纠错」与「首键不参与纠错」，小鹤音形输入 `cwui` | 稳定给出 4 码纠错候选「测试」，不出现 2 码前缀「希望」 |
| 首键纠错 | 开启「邻键纠错」并关闭「首键不参与纠错」，全拼输入 `bihao`（`b` 靠近 `n`） | 候选中尝试给出「你好」 |

<Aside type="caution" title="示例不是必定命中的承诺">
纠错与排序结果仍取决于当前方案词典、词频权重、原生切分、过滤器和触摸落点位置。若误码恰好对应另一个完整的原生正常词条，系统会优先保留原生候选，不再追加纠错。
</Aside>

## 从旧版手动 YAML 配置迁移

如果你曾按照旧版文档，在 `.custom.yaml` 中手动替换过翻译器入口（例如 `pinyin_correction_translator`、`double_pinyin_correction_translator`、`pinyin_correction_table_translator`、`double_pinyin_correction_table_translator`）并配置过 `pinyin_correction_enabled`、`double_pinyin_correction_enabled` 或 `key_correction` 参数：

1. **建议移除这些旧配置**，将 `engine/translators` 还原为方案原本的 `script_translator` 或 `table_translator`。
2. 删除不再需要的旧开关（`pinyin_correction_enabled` / `double_pinyin_correction_enabled`）以及皮肤按键中对应的 `rimeOption` 动作。
3. 在元书首页执行一次 **RIME → 部署**，此后直接在 **输入行为 → 纠错** 中统一开关即可。

<Aside type="note" title="关于旧入口兼容性">
旧版显式翻译器名称目前仍暂作向后兼容保留，但它们沿用旧版方案内开关逻辑，**不受应用内「输入行为 → 纠错」页面开关控制**。为获得动态按键区与基于真实触摸坐标的邻键纠错体验，建议统一还原为标准翻译器。
</Aside>
